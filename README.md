# TCP 文件传输工具

基于 TCP Socket 套接字实现的跨主机文件传输工具，支持**断点续传**、多客户端并发连接。

## 功能特性

- **可靠传输**：利用 TCP 协议确保文件传输的可靠性、有序性和完整性
- **断点续传**：客户端异常中断后重新连接，可以从上次下载的位置继续，无需重新下载
- **多客户端支持**：服务端采用多线程设计，可同时处理多个客户端连接
- **批量文件发送**：服务端可一次性指定多个文件，按顺序发送给客户端
- **传输进度显示**：服务端和客户端都实时显示传输进度百分比
- **文件完整性检查**：自动检测本地文件是否已完整存在，避免重复下载
- **高效传输**：使用 8KB 缓冲区提高传输效率

## 使用方法

### 1. 启动服务端

服务端启动时需要指定要发送的文件列表（一个或多个文件）：

```bash
./server file1.txt file2.jpg video.mp4 ...
```

服务端会：
- 监听本机 9413 端口
- 显示待发送文件列表
- 等待客户端连接
- 每个客户端连接后，依次发送所有指定文件

### 2. 启动客户端

客户端启动时需要指定服务端的 IP 地址：

```bash
./client <服务端IP地址>
```

例如：
```bash
./client 192.168.1.100
```

客户端会：
- 连接到指定的服务端
- 检查本地是否已有部分或完整文件
- 如有未完成下载，从断点继续
- 实时显示接收进度
- 保存到当前目录

## 通信协议

传输流程：

1. **建立连接**：客户端连接到服务端的 9413 端口
2. **服务端发送文件信息**：服务端先发送 `file_info_t` 结构体，包含：
   - 文件名（最多 100 字节）
   - 文件大小（64 位无符号整数）
   - 断点续传支持标记
3. **客户端回复下载请求**：客户端检查本地文件，回复需要下载的偏移位置
4. **服务端发送文件数据**：从指定偏移开始，以 8KB 为单位发送文件内容
5. **循环发送**：重复步骤 2-4，直到所有文件发送完毕
6. **断开连接**：服务端关闭连接

## 技术细节

- **端口**：默认使用 9413 端口
- **缓冲区**：8KB (8192 字节)，可在代码中调整
- **线程模型**：服务端每个客户端连接对应一个独立线程
- **信号处理**：忽略 SIGPIPE 信号防止程序崩溃
- **地址复用**：服务端启用 SO_REUSEADDR 支持快速重启
- **接收超时**：30秒无数据则超时

## 注意事项

1. 确保服务端指定的文件存在且可读
2. 确保网络通畅，防火墙允许 9413 端口通信
3. 文件名长度不超过 100 字节
4. 客户端当前目录需要有写入权限
5. 断点续传依赖文件名匹配，请不要修改未完成下载的文件名
6. 如果本地文件大小大于服务端，会自动重新下载
